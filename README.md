# toolhub

블로그 글감을 찾기 위한 로컬 키워드 도구입니다.
여러 소스의 실시간 키워드를 모아 날짜별로 기록하고, 네이버 검색광고 API로 검색량·경쟁도·연관 키워드를 확인합니다.

- 내 PC에서만 실행합니다. 수집 데이터는 `data/`에 쌓이며 git에 올라가지 않습니다.
- 비용 없이 쓸 수 있습니다. 네이버 검색광고 API도 광고비 없이 무료로 쓸 수 있습니다.

## 시작하기

### 1. 설치

Node.js 24 이상이 필요합니다.

```bash
npm install
```

### 2. 네이버 검색광고 API 키 설정 (선택)

키가 없어도 실시간 키워드 수집과 기록은 동작합니다. 키를 넣으면 검색량, 경쟁도, 연관 키워드가 추가로 표시됩니다.

1. [searchad.naver.com](https://searchad.naver.com)에 가입합니다. 네이버 아이디로 가입할 수 있고, 개인도 사업자등록 없이 가입됩니다.
2. 광고 시스템 → **도구 → API 사용 관리**에서 API 사용을 신청하고 키 세 개를 발급받습니다.
3. 템플릿을 복사한 뒤 값을 채웁니다.

```bash
cp apps/web/.env.example apps/web/.env.local
```

```ini
NAVER_SEARCHAD_API_KEY=액세스 라이선스
NAVER_SEARCHAD_SECRET_KEY=비밀키
NAVER_SEARCHAD_CUSTOMER_ID=CUSTOMER_ID
```

`.env.local`은 git에 올라가지 않습니다. 키를 바꾼 뒤에는 웹 서버를 재시작해야 합니다.

### 3. 실행

```bash
npm run web
```

브라우저에서 http://localhost:3000 을 엽니다.

## 사용 방법

상단 메뉴에서 페이지를 고릅니다.

### 실시간 (`/`)

- Google Trends, 네이트, signal.bz의 지금 순위를 한 화면에 보여줍니다.
- **페이지를 열거나 새로고침할 때마다** 처음 보는 키워드가 오늘 기록에 추가됩니다. 같은 키워드는 한 번만 기록됩니다.
- 순위 옆 표시: `NEW` 신규 진입, `▲`/`▼` 순위 변동, 숫자는 구글 검색량(대략값)입니다.
- 키워드를 누르면 관련 뉴스 기사로 이동합니다.

> 기록은 이 페이지를 연 시점에만 쌓입니다. 하루 동안 자주 열어볼수록 그날 뜬 키워드를 빠짐없이 모을 수 있습니다.

### 키워드 기록 (`/history`)

- 날짜를 골라 그날 뜬 키워드 전체를 봅니다.
- **최근 순**: 처음 본 시각이 늦은 키워드가 위로 옵니다.
- **검색량 순**: 네이버 월간 검색량(PC+모바일)이 많은 키워드가 위로 옵니다.
- **경쟁도**: 네이버 검색광고 기준 `낮음`·`중간`·`높음`입니다. 검색량이 많고 경쟁도가 낮을수록 글감으로 좋습니다.
- 키워드를 누르면 **키워드 분석** 페이지로 이동합니다.

검색량은 키워드당 하루에 한 번만 조회해서 저장합니다. 네이버 API의 호출 한도 때문에 한 번 열 때 최대 50개까지만 조회하고, 남은 키워드가 있으면 안내가 표시됩니다. 새로고침하면 이어서 조회합니다.

> 뉴스 제목처럼 긴 문장형 키워드는 검색량이 `-`로 나오기 쉽습니다. 이럴 때는 키워드 분석에서 짧은 핵심어로 다시 조회해 보세요.

### 키워드 분석 (`/keyword`)

- 키워드를 입력하면 그 키워드의 **월간 검색량(PC/모바일), 경쟁도, 월평균 클릭**을 카드로 보여줍니다.
- 아래에는 **연관 키워드를 검색량 상위 100개까지** 보여줍니다. 연관 키워드를 누르면 계속 파고들 수 있습니다.
- `네이버 검색`, `구글 검색` 버튼으로 실제 검색 결과(경쟁 글)를 바로 확인할 수 있습니다.

### 초안 (`/drafts`)

Claude 데스크톱 앱(`save_draft`)이나 `/blog-draft`가 `drafts/`에 저장한 초안을 발행 직전까지 정리하는 화면입니다.

- **미리보기**: 본문을 블로그에 올렸을 때의 모습으로 보여줍니다. 티스토리·Blogger는 HTML 그대로, 네이버는 `■` 소제목·`★` 강조를 서식으로 바꿔 보여줍니다. 사람이 채울 자리는 형광펜으로 표시됩니다 (파랑: 이미지, 노랑: 직접 작성, 빨강: 확인 필요).
- **항목별 복사**: 제목 후보, 메타 설명, 태그, 본문, 스레드 홍보글을 각각 복사 버튼으로 가져갑니다. 글자 수와 플랫폼 권장 분량도 함께 표시합니다.
- **발행 전 체크리스트**: 본문 속 `[이미지]`, `[직접 작성]`, `[확인 필요]`를 목록으로 모아 체크합니다. 체크 상태는 브라우저에 기억됩니다.
- **붙여넣기 안내**: 플랫폼별로 에디터 어디에 붙여넣는지 알려줍니다.

> 초안 형식(`docs/prompts/writing.md`의 출력 형식)과 다르게 작성된 파일은 원본 마크다운을 그대로 보여주고 통째로 복사할 수 있습니다.

### 추천 흐름

1. **실시간**에서 오늘 뜨는 이슈를 확인합니다.
2. **키워드 기록**을 검색량 순으로 정렬해, 검색량이 많고 경쟁도가 낮은 키워드를 고릅니다.
3. **키워드 분석**에서 연관 키워드를 펼쳐 롱테일 키워드를 찾습니다. 예: "국민연금" → "국민연금 수령나이 조회".
4. 네이버·구글 검색 버튼으로 경쟁 글을 확인한 뒤 글을 씁니다. 초안은 아래 **Claude로 글쓰기**를 참고하세요.

## Claude로 글쓰기

toolhub는 데이터를 정리하고, 글감 판단과 초안 작성은 [claude.ai](https://claude.ai)에서 합니다.
claude.ai **프로젝트**에 지침을 한 번 등록해 두면, 이후에는 데이터(브리프)만 붙여넣으면 됩니다.

### 처음 한 번: 프로젝트 만들기

1. claude.ai에서 새 프로젝트를 만듭니다. (예: "블로그 작성")
2. [docs/prompts/project-instructions.md](docs/prompts/project-instructions.md)를 열어 **"내 블로그 정보"의 `[ ]` 부분을 내 블로그에 맞게 채웁니다.**
3. 그 파일 내용 전체를 프로젝트의 **지침(Instructions)** 에 붙여넣습니다.
4. 나머지 파일을 프로젝트 **지식(Knowledge)** 에 파일로 올립니다.

| 파일 | 내용 |
|---|---|
| [planning.md](docs/prompts/planning.md) | 글감 선정 규칙 |
| [writing.md](docs/prompts/writing.md) | 초안 작성 공통 규칙 (구조, 키워드 사용, 이미지·경험 자리 표시) |
| [platforms/tistory.md](docs/prompts/platforms/tistory.md) | 티스토리: HTML 모드용 본문 |
| [platforms/blogger.md](docs/prompts/platforms/blogger.md) | Blogger: HTML 본문, 검색 설명, 퍼머링크 |
| [platforms/naver.md](docs/prompts/platforms/naver.md) | 네이버: 스마트에디터용 일반 텍스트 |
| [threads.md](docs/prompts/threads.md) | 블로그 홍보용 스레드 글 3개 |

> 프롬프트를 고치면 claude.ai 프로젝트에도 다시 올려야 반영됩니다. 원본은 이 저장소의 `docs/prompts/`이며 git으로 수정 이력을 관리합니다.

### 매번: 키워드 하나로 초안 받기

쓸 키워드를 정했다면 두 가지 방법 중 편한 쪽을 씁니다.

**방법 A. 웹에서 복사 → claude.ai에 붙여넣기**

1. **키워드 분석**에서 키워드를 조회하고, 플랫폼(티스토리·Blogger·네이버)을 고른 뒤 **✍ 브리프 복사**를 누릅니다.
   - **키워드 기록** 표의 각 줄 맨 앞 **✍** 버튼으로도 바로 복사할 수 있습니다. 플랫폼은 페이지 위쪽에서 고르며, 마지막 선택이 기억됩니다.
2. claude.ai 프로젝트 대화창에 붙여넣으면 초안이 나옵니다.

**방법 B. Claude Code 명령 한 줄 (복사 없음)**

이 저장소에서 Claude Code를 열고 입력합니다.

```
/blog-draft 국민연금 수령나이 티스토리
/blog-draft 국민연금 수령나이, 기초연금 신청방법 네이버
```

- 키워드 뒤에 플랫폼(`티스토리`, `blogger`, `네이버`)을 붙입니다. 생략하면 티스토리입니다. 쉼표로 여러 키워드를 한 번에 줄 수 있습니다.
- Claude Code가 검색량과 연관 키워드를 조회하고, `docs/prompts/` 규칙에 따라 웹 검색으로 사실을 확인한 뒤 `drafts/2026-10-29-국민연금-수령나이-tistory.md` 같은 파일로 초안을 저장합니다. `drafts/`는 git에 올라가지 않습니다.
- claude.ai 프로젝트를 만들지 않아도 됩니다. 단, `docs/prompts/project-instructions.md`의 "내 블로그 정보"는 채워 두세요.

브리프만 터미널에서 확인하려면 이렇게 실행합니다.

```bash
npm run --silent brief -- "국민연금 수령나이" --platform tistory
```

> 네이버 검색광고는 "국민연금 수령나이" 같은 롱테일 키워드에 연관 키워드를 거의 주지 않습니다. 그래서 각 단어("국민연금", "수령나이")의 연관 키워드도 함께 조회한 뒤, 키워드의 단어를 많이 포함한 순으로 브리프에 넣습니다.

**방법 C. Claude 데스크톱 앱에서 대화로 (MCP, 추천)**

toolhub MCP 서버를 데스크톱 앱에 연결하면, Claude가 키워드 데이터와 글쓰기 규칙을 직접 조회합니다. 복사·붙여넣기도, 터미널도 필요 없습니다. 설정은 아래 [Claude 데스크톱 앱 연결 (MCP)](#claude-데스크톱-앱-연결-mcp)을 참고하세요.

```
오늘 뜬 키워드 중에 블로그로 쓸 만한 거 3개 골라줘
→ 2번으로 네이버 글 써줘
→ 저장하고 웹에서 열어줘      (초안 화면에서 미리보기·체크리스트·복사)
```

### 브리프 형식

직접 붙여넣을 때는 아래 형식을 따릅니다. 첫 줄을 보고 Claude가 작업을 구분합니다.

**① 글감 고르기** (선택): 오늘 쓸 키워드를 Claude에게 골라 달라고 할 때, 키워드 기록(검색량 순)의 상위 키워드를 표로 붙여넣습니다.

```
[글감 브리핑]
날짜: 2026-10-29
| 키워드 | 월간 검색량 | 경쟁도 | 소스 | 처음 본 시각 | 관련 뉴스 |
|---|---|---|---|---|---|
| 국민연금 | 287,000 | 낮음 | Google Trends | 13:49 | 국민연금 가입기간 늘려… |
```

→ 추천 글감 3~5개, 수명(상시·시즌·반짝), 타깃 키워드 후보, 제목 예시, 추천 플랫폼을 받습니다.

**② 초안 받기**: ✍ 버튼이 만들어 주는 형식입니다.

```
[글쓰기 브리프]
플랫폼: 티스토리
키워드: 국민연금 수령나이
월간 검색량: 58,040 (PC 8,440 / 모바일 49,600) · 경쟁도: 중간
연관 키워드 (관련 높은 순):
| 키워드 | 월간 검색량 | 경쟁도 |
|---|---|---|
| 국민연금 | 287,000 | 낮음 |
| 국민연금계산법 | 660 | 중간 |
```

→ 제목 후보, 메타 설명, 태그, 플랫폼 형식의 본문, 이미지 목록, 사람이 할 일, 참고 출처, 스레드 홍보글 3개를 받습니다.

### 발행 전 직접 할 일

초안에는 사람이 채울 자리가 표시돼 있습니다. **AI 초안을 그대로 발행하지 마세요.** 검색 엔진과 애드센스는 사람이 다듬은, 경험이 담긴 글을 더 좋게 평가합니다.

| 표시 | 할 일 |
|---|---|
| `[이미지: 내용 \| alt: … \| 추천: …]` | 이미지를 직접 캡처·촬영하거나 무료 사진을 넣고, alt(대체 텍스트)를 입력합니다 |
| `[직접 작성: …]` | 내 경험이나 의견을 씁니다 |
| `[확인 필요: …]` | 공식 출처에서 확인한 뒤 고치거나 지웁니다 |

> 뉴스 사진이나 검색으로 찾은 이미지는 쓰지 마세요. 저작권 문제로 애드센스 승인 거절이나 정지 사유가 됩니다.

## Claude 데스크톱 앱 연결 (MCP)

### 설정 (처음 한 번)

1. 터미널에서 두 경로를 확인합니다.

   ```bash
   which node   # 예: /usr/local/bin/node
   pwd          # 저장소 루트에서 실행. 예: /Users/me/source/toolhub
   ```

2. 데스크톱 앱 설정 파일 `~/Library/Application Support/Claude/claude_desktop_config.json`의 `mcpServers`에 추가합니다. 경로는 1번에서 확인한 값으로 바꾸고, **반드시 절대 경로**를 씁니다. 다른 서버가 이미 있으면 그 옆에 추가합니다.

   ```json
   {
     "mcpServers": {
       "toolhub": {
         "command": "/usr/local/bin/node",
         "args": [
           "--env-file-if-exists=/Users/me/source/toolhub/apps/web/.env.local",
           "/Users/me/source/toolhub/packages/mcp/src/server.ts"
         ]
       }
     }
   }
   ```

3. 데스크톱 앱을 **완전히 종료(⌘Q)했다가 다시 실행**합니다. 대화창의 도구 메뉴에 `toolhub`가 보이면 연결된 것입니다.

> Claude Code는 저장소의 `.mcp.json`으로 같은 서버를 자동으로 인식합니다. 처음 열 때 사용 승인을 묻습니다.

### 쓸 수 있는 도구

| 도구 | 하는 일 |
|---|---|
| `get_live_keywords` | 지금 실시간 키워드 조회 (오늘 기록에도 추가) |
| `get_daily_keywords` | 날짜별 기록을 검색량·경쟁도와 함께 `[글감 브리핑]` 표로 조회 |
| `analyze_keyword` | 키워드 검색량·경쟁도와 연관 키워드 |
| `get_writing_rules` | `docs/prompts/`의 글감 선정·초안 작성 규칙 |
| `get_writing_brief` | 키워드 + 플랫폼 → `[글쓰기 브리프]` |
| `save_draft` | 초안을 `drafts/`에 파일로 저장 |
| `open_web` | toolhub 웹을 브라우저로 열기 (http://localhost:3100). **항상 로컬 main 브랜치의 최신 커밋으로 실행**하며, 꺼져 있거나 옛 커밋이면 (재)시작한 뒤 엽니다. 페이지(실시간·기록·분석·초안)와 키워드·날짜·초안 파일 지정 가능 |
| `stop_web` | `open_web`으로 시작한 웹 서버 끄기 (터미널에서 직접 띄운 서버는 끄지 않음) |

예: "toolhub 웹 열어줘", "어제 키워드 기록 화면 열어줘", "국민연금 수령나이 분석 화면 띄워줘", "방금 저장한 초안 웹에서 열어줘", "웹 서버 꺼줘"

#### `open_web`은 어떤 코드로 실행되나

| | 개발용 `npm run web` | 사용용 `open_web` |
|---|---|---|
| 주소 | http://localhost:3000 | http://localhost:3100 |
| 코드 | 지금 작업 중인 코드 (커밋 안 한 수정 포함) | **로컬 main 브랜치의 최신 커밋** |
| 실행 위치 | 이 저장소 | `~/.toolhub/runtime/toolhub` (git worktree) |
| 데이터·키 | `data/`, `apps/web/.env.local` | 같은 파일을 공유 |

- main에 커밋하면, 다음에 `open_web`을 부를 때 실행 폴더를 새 커밋으로 맞추고 웹을 재시작합니다. 커밋하지 않은 수정이나 다른 브랜치 작업은 반영되지 않습니다.
- 의존성(`package-lock.json`)이 바뀐 커밋이면 실행 폴더에 `npm install`을 다시 합니다. 오래 걸리면 Claude가 "준비 중"이라고 답하는데, 잠시 후 다시 요청하면 이어서 엽니다.
- `open_web`으로 시작한 웹 서버는 데스크톱 앱을 꺼도 계속 실행됩니다. 다 쓰면 "웹 서버 꺼줘"로 끄세요. 로그는 `.toolhub/web.log`에 남습니다.
- `git worktree list`에 실행 폴더가 함께 보이는 것은 정상입니다. 지우고 싶으면 `git worktree remove --force ~/.toolhub/runtime/toolhub`를 실행하면 되고, 다음 `open_web` 때 다시 만들어집니다.
- 3100번 포트를 다른 프로그램이 쓰고 있으면 MCP 설정의 `env`에 `"TOOLHUB_WEB_PORT": "3200"`처럼 다른 포트를 지정합니다.

대화창의 `+` 메뉴에서 **프롬프트**도 고를 수 있습니다.

- `blog_draft`: 키워드와 플랫폼을 넣으면 규칙과 브리프가 담긴 초안 요청이 만들어집니다.
- `pick_topics`: 그날 기록으로 글감 선정 요청을 만듭니다.

> MCP로 쓸 때는 claude.ai 프로젝트가 없어도 됩니다. Claude가 `get_writing_rules`로 규칙을 직접 읽습니다. 단, `docs/prompts/project-instructions.md`의 "내 블로그 정보"는 채워 두세요.

## 터미널에서 수집하기

웹을 띄우지 않고 터미널에서 바로 수집해 기록할 수도 있습니다.

```bash
npm run collect                            # 전체 소스
npm run collect -- --sources google,nate   # 일부 소스만
```

## 데이터

```
data/
  2026-10-29.json   # 하루에 파일 하나, 키워드당 한 줄
```

| 필드 | 설명 |
|---|---|
| `keyword` | 키워드 |
| `sources` | 잡힌 소스 (`google`, `nate`, `signal`) |
| `firstSeen` | 처음 본 시각 (KST) |
| `bestRank` | 그날 최고 순위 |
| `maxTraffic` | 구글 트렌드 검색량 (대략값) |
| `related`, `url` | 관련 뉴스 제목과 링크 |
| `stats` | 네이버 검색광고 검색량·경쟁도. 아직 조회하지 않았으면 필드가 없고, 데이터가 없으면 `null` |

데이터 위치는 환경변수 `TOOLHUB_DATA_DIR`로 바꿀 수 있습니다.

```
toolhub/

│       ├── collect.ts         # 수집 → 기록 → 검색량 채우기 흐름

│       ├── brief.ts           # 글쓰기 브리프 생성 (웹 버튼·CLI 공용)

│       ├── page.tsx           # 실시간
```

## 알아둘 점

- 네이트, signal.bz는 공식 API가 아닌 공개 엔드포인트를 사용합니다. 사이트가 바뀌면 해당 소스만 "조회 실패"로 표시되고, 나머지 소스는 계속 동작합니다.
- 네이버 검색광고 API는 호출 한도가 낮습니다. 요청 사이에 1초 간격을 두고, 한도에 걸리면 자동으로 재시도합니다.
- 네이버 검색광고 기준 검색량이 10 미만이면 `<10`으로 표시됩니다.
