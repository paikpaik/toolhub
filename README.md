# toolhub

내 PC에서 쓰는 **일정 관리 + 블로그 자동화** 도구입니다.

- **일정 관리**: TickTick·Linear 스타일의 할 일 관리. 자연어 빠른 추가, 목록·보드·캘린더, 프로젝트·태그·반복. Claude 데스크톱 앱에서 대화로 추가·수정할 수 있습니다.
- **블로그 자동화**: 여러 소스의 실시간 키워드를 모아 날짜별로 기록하고, 네이버 검색광고·API HUB로 검색량·경쟁도·추이·연관 키워드를 확인해 글감을 고르고 초안·썸네일까지 만듭니다.

- 내 PC에서만 실행합니다. 데이터(키워드 기록, 일정)는 `data/`에 쌓이며 git에 올라가지 않습니다.
- 비용 없이 쓸 수 있습니다. 네이버 검색광고 API도 광고비 없이 무료로 쓸 수 있습니다.

## 시작하기

### 1. 설치

Node.js 24 이상이 필요합니다.

```bash
npm install
```

### 2. 네이버 검색광고 API 키 설정 (선택)

키가 없어도 실시간 키워드 수집과 기록은 동작합니다. 키를 넣으면 검색량, 경쟁도, 연관 키워드가 추가로 표시됩니다.

1. [searchad.naver.com](https://searchad.naver.com)에 가입합니다. 네이버 아이디로 가입할 수 있고, 개인도 사업자등록 없이 가입됩니다.
2. 광고 시스템 → **도구 → API 사용 관리**에서 API 사용을 신청하고 키 세 개를 발급받습니다.
3. 템플릿을 복사한 뒤 값을 채웁니다.

```bash
cp apps/web/.env.example apps/web/.env.local
```

```ini
NAVER_SEARCHAD_API_KEY=액세스 라이선스
NAVER_SEARCHAD_SECRET_KEY=비밀키
NAVER_SEARCHAD_CUSTOMER_ID=CUSTOMER_ID
```

`.env.local`은 git에 올라가지 않습니다. 키를 바꾼 뒤에는 웹 서버를 재시작해야 합니다.

### 2-1. NAVER API HUB 키 설정 (선택)

검색 추이, 블로그 문서 수(포화도), 지식iN 질문, 상위 블로그 글, 뉴스, 카페 글, 장소 정보, 쇼핑 트렌드를 쓰려면 필요합니다. 키가 없으면 이 부분만 빠지고 나머지는 그대로 동작합니다.

1. [네이버 클라우드 플랫폼](https://www.ncloud.com)에 가입하고 콘솔에 로그인합니다. (2026년 7월 31일부터 검색·데이터랩 API의 신규 발급은 개발자센터가 아니라 NAVER API HUB에서 합니다.)
2. 콘솔 오른쪽 위 **리전 & 플랫폼**에서 한국 리전을 고르고 적용합니다.
3. **Menu → All Services → Application Services → NAVER API HUB → Application → [Application 등록]**
4. 사용할 API를 고릅니다: **검색어 트렌드, 쇼핑 인사이트, 블로그·지식iN·뉴스·카페글·지역 검색**
5. 등록한 Application의 **API 관리 → 인증 정보**에서 Client ID와 Client Secret을 복사해 `.env.local`에 추가합니다.

```ini
NAVER_API_HUB_CLIENT_ID=Client ID
NAVER_API_HUB_CLIENT_SECRET=Client Secret
```

> NAVER API HUB는 종량제지만 현재 한시적으로 무료이며, 유료 전환 시 사전 공지된다고 안내돼 있습니다. 검색 API는 하루 25,000회까지 호출할 수 있고, 이 도구의 사용량은 하루 수십 회 수준입니다.

### 3. 실행

```bash
npm run web
```

브라우저에서 http://localhost:3000 을 엽니다. 첫 화면은 일정 관리의 **오늘**입니다.

## 화면 구성

왼쪽 사이드바에서 메뉴를 고릅니다. 좁은 화면에서는 왼쪽 위 ☰ 버튼으로 엽니다.

```
일정 관리      오늘 · 다음 7일 · 날짜 없음 · 전체 · 보드 · 캘린더 · 완료됨
               프로젝트 목록 · 태그 목록
블로그 자동화  실시간 · 키워드 기록 · 키워드 분석 · 초안 · 썸네일
```

> 블로그 메뉴는 `/blog/...` 주소를 씁니다. 예전 주소(`/history`, `/keyword`, `/drafts`, `/thumbnail`)로 들어와도 새 주소로 자동 이동합니다.

## 일정 관리 (`/tasks`)

### 빠른 추가 (자연어)

맨 위 입력창에 한 줄로 쓰면 날짜·시간·우선순위·태그·프로젝트·반복을 알아서 해석합니다. 입력하는 동안 해석 결과가 칩으로 미리 보입니다. 아무 화면에서나 **C** 키를 누르면 입력창으로 갑니다.

```
내일 오후 3시 국민연금 글 발행 #블로그 @블로그 운영 !높음 매주
```

| 쓰는 법 | 예 |
|---|---|
| 날짜 | `오늘` `내일` `모레` `월요일` `이번 주 금요일` `다음 주 월요일` `주말` `11월 3일` `11/3` `2026-11-03` `3일 뒤` |
| 시간 | `오전 9시` `오후 3시 30분` `3시반` `15시` `15:30` (시간만 쓰면 오늘) |
| 우선순위 | `!긴급` `!높음` `!보통` `!낮음` 또는 `!1`~`!4` |
| 태그 | `#태그` (여러 개 가능) |
| 프로젝트 | `@프로젝트` — 있는 이름이면 띄어쓰기가 있어도 맞춰지고(`@블로그 운영`), 없는 이름이면 새로 만듭니다 |
| 반복 | `매일` `매주` `매월`(`매달`) `매년` |

보고 있는 화면에 따라 기본값이 붙습니다: **오늘** 화면에서는 날짜를 안 쓰면 오늘, **프로젝트·태그** 화면에서는 그 프로젝트·태그, **캘린더**에서 날짜를 누른 뒤에는 그 날짜.

### 보기

| 보기 | 내용 |
|---|---|
| 오늘 | 오늘 할 일과 지난 일정 (사이드바 숫자가 빨간색이면 지난 일정이 있다는 뜻) |
| 다음 7일 · 전체 | 지난 일정 / 오늘 / 내일 / 7일 안 / 나중 / 날짜 없음으로 묶어서 |
| 날짜 없음 | 날짜를 정하지 않은 할 일 (받은 편지함) |
| 보드 | 상태별 칸반 (할 일·진행 중·완료·취소). 카드를 다른 칸으로 끌면 상태가 바뀝니다 |
| 캘린더 | 월간 달력. 날짜를 누르면 그 날짜로 추가하고, 할 일을 다른 날짜로 끌면 마감일이 바뀝니다 |
| 완료됨 | 완료·취소한 할 일 (최근 순) |
| 프로젝트 · 태그 | 사이드바에서 고르면 그 프로젝트·태그의 할 일만. 프로젝트는 이름 바꾸기·삭제 가능 (삭제해도 할 일은 남음) |

### 할 일 다루기

- **완료**: 왼쪽 동그라미를 누릅니다. 동그라미 테두리 색은 우선순위입니다 (빨강 긴급 · 주황 높음 · 노랑 보통 · 보라 낮음). 반쯤 찬 동그라미는 진행 중입니다.
- **상세 편집**: 할 일을 누르면 오른쪽에 패널이 열립니다. 상태·우선순위·마감일·시간·반복·프로젝트·태그·링크·하위 할 일·메모를 고칠 수 있고, 바꾸는 즉시 저장됩니다. `Esc`로 닫습니다.
- **반복 할 일**: 완료하면 완료 기록은 남고 다음 회차가 새로 생깁니다 (매주면 7일 뒤 같은 시간).
- **링크**: 초안·키워드 분석 주소 등을 붙여 두면 상세 패널에서 바로 열 수 있습니다.
- 주소에 `?task=12`를 붙이면 #12의 상세가 열린 채로 시작합니다.
- Claude 데스크톱 앱(MCP)에서 바꾼 내용은 창으로 돌아오거나 15초마다 자동으로 반영됩니다.

## 블로그 자동화

### 실시간 (`/blog`)

- Google Trends, 네이트, signal.bz의 지금 순위를 한 화면에 보여줍니다.
- **페이지를 열거나 새로고침할 때마다** 처음 보는 키워드가 오늘 기록에 추가됩니다. 같은 키워드는 한 번만 기록됩니다.
- 순위 옆 표시: `NEW` 신규 진입, `▲`/`▼` 순위 변동, 숫자는 구글 검색량(대략값)입니다.
- 키워드를 누르면 관련 뉴스 기사로 이동합니다.

> 기록은 이 페이지를 연 시점에만 쌓입니다. 하루 동안 자주 열어볼수록 그날 뜬 키워드를 빠짐없이 모을 수 있습니다.

### 키워드 기록 (`/blog/history`)

- 날짜를 골라 그날 뜬 키워드 전체를 봅니다.
- **기간**: `하루`, `7일`, `30일` 중에서 고릅니다. 7일·30일은 고른 날짜까지 그 기간 동안 뜬 키워드를 합쳐 보여주고, 키워드마다 **등장 일수**(`하루`·`2일`·`지속`(3일 이상))와 처음·마지막으로 본 날을 표시합니다.
  - 실시간 키워드는 날마다 대부분 바뀝니다. 여러 날 연속으로 뜬 키워드는 반짝 이슈가 아니라 관심이 이어지는 주제일 가능성이 높아 글감으로 눈여겨볼 만합니다.
- **정렬**: 최근 순(처음 본 시각이 늦은 순), 검색량 순(네이버 월간 검색량 PC+모바일), 등장 일수 순(여러 날 보기 기본값)
- **경쟁도**: 네이버 검색광고 기준 `낮음`·`중간`·`높음`입니다. 검색량이 많고 경쟁도가 낮을수록 글감으로 좋습니다.
- **초안 ✓**: 이미 초안을 쓴 키워드에 표시되고, 누르면 그 초안으로 이동합니다. 같은 주제로 두 번 쓰는 것을 막아 줍니다.
- 키워드를 누르면 **키워드 분석** 페이지로 이동합니다.

검색량은 키워드당 하루에 한 번만 조회해서 저장합니다. 네이버 검색광고 API는 호출 한도 때문에 요청 사이에 1초씩 쉬어야 해서(5개씩), 새 키워드가 많으면 조회에 수 초가 걸립니다. 그래서 **페이지는 바로 보여주고 검색량은 뒤에서 채웁니다.** 위쪽에 "검색량을 조회하고 있어요 (남은 키워드 n개)"가 보이는 동안 표의 숫자가 차례로 채워집니다. 또 **실시간** 페이지에서 새 키워드가 기록되면 그때 바로 뒤에서 조회를 시작하므로, 키워드 기록을 열 즈음엔 대부분 채워져 있습니다.

> 뉴스 제목처럼 긴 문장형 키워드는 검색량이 `-`로 나오기 쉽습니다. 이럴 때는 키워드 분석에서 짧은 핵심어로 다시 조회해 보세요.

### 키워드 분석 (`/blog/keyword`)

- 키워드를 입력하면 그 키워드의 **월간 검색량(PC/모바일), 경쟁도, 월평균 클릭**을 카드로 보여줍니다.
- NAVER API HUB 키가 있으면 아래 정보가 함께 나옵니다.
  - **검색 추이**: 최근 24개월 네이버 검색 추이 차트와 해석 (시즌·급등 이력·상승세·하락세·꾸준함·변동 큼)
  - **블로그 문서 수와 포화도**: 블로그 문서 수 ÷ 월간 검색량. 10배 이하면 `기회`, 50배 이하면 `보통`, 그 이상이면 `높음` (참고용 기준. 블로그 문서 수는 지금까지 쌓인 전체 글 수라 비율이 크게 나옵니다. 예: 국민연금 수령나이 2배, 에어프라이어 추천 67배, 다이어트 800배)
  - **실제 질문**(지식iN), **상위 블로그 글**, **최신 뉴스**, **카페 글**, **장소 검색 결과**
- 아래에는 **연관 키워드를 검색량 상위 100개까지** 보여줍니다. 연관 키워드를 누르면 계속 파고들 수 있습니다.
- `네이버 검색`, `구글 검색` 버튼으로 실제 검색 결과(경쟁 글)를 바로 확인할 수 있습니다.

### 초안 (`/blog/drafts`)

Claude 데스크톱 앱(`save_draft`)이나 `/blog-draft`가 `drafts/`에 저장한 초안을 발행 직전까지 정리하는 화면입니다.

- **미리보기**: 본문을 블로그에 올렸을 때의 모습으로 보여줍니다. 티스토리·Blogger는 HTML 그대로, 네이버는 `■` 소제목·`★` 강조를 서식으로 바꿔 보여줍니다. 사람이 채울 자리는 형광펜으로 표시됩니다 (파랑: 이미지, 노랑: 직접 작성, 빨강: 확인 필요).
- **항목별 복사**: 제목 후보, 메타 설명, 태그, 본문, 스레드 홍보글을 각각 복사 버튼으로 가져갑니다. 글자 수와 플랫폼 권장 분량도 함께 표시합니다.
- **발행 전 체크리스트**: 본문 속 `[이미지]`, `[직접 작성]`, `[확인 필요]`를 목록으로 모아 체크합니다. 체크 상태는 브라우저에 기억됩니다.
- **붙여넣기 안내**: 플랫폼별로 에디터 어디에 붙여넣는지 알려줍니다.

> 초안 형식(`docs/prompts/writing.md`의 출력 형식)과 다르게 작성된 파일은 원본 마크다운을 그대로 보여주고 통째로 복사할 수 있습니다.

### 썸네일 (`/blog/thumbnail`)

블로그 대표 이미지를 만듭니다. 초안 화면의 **썸네일 만들기** 버튼을 누르면 추천 제목이 채워진 채로 열립니다.

- **제목**: `*단어*`로 감싼 부분은 강조색으로 그려집니다. 줄바꿈을 넣으면 그 위치에서 줄이 나뉘고, 그 밖에는 너비에 맞춰 자동으로 줄을 바꾸고 글자 크기를 맞춥니다.
- **부제·라벨**(선택): 예) 부제 "2026년 기준 총정리", 라벨 "정보"·"리뷰"·"맛집"
- **템플릿 4종**: 중앙 정렬, 좌측 정렬 + 라벨, 강조 바, 프레임
- **크기 3종**: 1200×630(티스토리·Blogger 공유용), 1080×1080(네이버·스레드 정사각), 1280×720(16:9)
- **글꼴 3종**: 깔끔(Noto Sans KR), 임팩트(Black Han Sans), 부드러움(Jua)
- **색 조합**: 프리셋 6가지 또는 배경·글자·강조색 직접 지정
- **PNG 다운로드** 또는 **이미지 복사**(블로그 에디터에 바로 붙여넣기)

블로그 이름·템플릿·크기·글꼴·색은 브라우저에 기억돼 다음에도 같은 스타일로 시작합니다. 썸네일 스타일을 통일하면 블로그가 한눈에 알아보기 쉬워집니다.

### 추천 흐름

1. **실시간**에서 오늘 뜨는 이슈를 확인합니다.
2. **키워드 기록**을 검색량 순으로 정렬해, 검색량이 많고 경쟁도가 낮은 키워드를 고릅니다.
3. **키워드 분석**에서 연관 키워드를 펼쳐 롱테일 키워드를 찾습니다. 예: "국민연금" → "국민연금 수령나이 조회".
4. 네이버·구글 검색 버튼으로 경쟁 글을 확인한 뒤 글을 씁니다. 초안은 아래 **Claude로 글쓰기**를 참고하세요.

## Claude로 글쓰기

toolhub는 데이터를 정리하고, 글감 판단과 초안 작성은 [claude.ai](https://claude.ai)에서 합니다.
claude.ai **프로젝트**에 지침을 한 번 등록해 두면, 이후에는 데이터(브리프)만 붙여넣으면 됩니다.

### 처음 한 번: 프로젝트 만들기

1. claude.ai에서 새 프로젝트를 만듭니다. (예: "블로그 작성")
2. [docs/prompts/project-instructions.md](docs/prompts/project-instructions.md)를 열어 **"내 블로그 정보"의 `[ ]` 부분을 내 블로그에 맞게 채웁니다.**
3. 그 파일 내용 전체를 프로젝트의 **지침(Instructions)** 에 붙여넣습니다.
4. 나머지 파일을 프로젝트 **지식(Knowledge)** 에 파일로 올립니다.

| 파일 | 내용 |
|---|---|
| [planning.md](docs/prompts/planning.md) | 글감 선정 규칙 |
| [writing.md](docs/prompts/writing.md) | 초안 작성 공통 규칙 (브리프 항목 쓰는 법, 키워드 사용, 이미지·경험 자리 표시) |
| [types/info.md](docs/prompts/types/info.md) | 정보 글: 제도·방법·비교 |
| [types/review.md](docs/prompts/types/review.md) | 리뷰 글: 상품·서비스 사용기 (직접 경험 자리 많음) |
| [types/place.md](docs/prompts/types/place.md) | 장소 글: 맛집·여행지·시설 방문기 (직접 촬영 사진 자리 많음) |
| [platforms/tistory.md](docs/prompts/platforms/tistory.md) | 티스토리: HTML 모드용 본문 |
| [platforms/blogger.md](docs/prompts/platforms/blogger.md) | Blogger: HTML 본문, 검색 설명, 퍼머링크 |
| [platforms/naver.md](docs/prompts/platforms/naver.md) | 네이버: 스마트에디터용 일반 텍스트 |
| [threads.md](docs/prompts/threads.md) | 블로그 홍보용 스레드 글 3개 |

> 프롬프트를 고치면 claude.ai 프로젝트에도 다시 올려야 반영됩니다. 원본은 이 저장소의 `docs/prompts/`이며 git으로 수정 이력을 관리합니다.

### 매번: 키워드 하나로 초안 받기

쓸 키워드를 정했다면 두 가지 방법 중 편한 쪽을 씁니다.

**방법 A. 웹에서 복사 → claude.ai에 붙여넣기**

1. **키워드 분석**에서 키워드를 조회하고, 글 유형(정보·리뷰·장소), 구성(자동 또는 A~D), 플랫폼(티스토리·Blogger·네이버)을 고른 뒤 **✍ 브리프 복사**를 누릅니다.
   - **키워드 기록** 표의 각 줄 맨 앞 **✍** 버튼으로도 바로 복사할 수 있습니다. 유형·플랫폼은 마지막 선택이 기억됩니다.
2. claude.ai 프로젝트 대화창에 붙여넣으면 초안이 나옵니다.

**방법 B. Claude Code 명령 한 줄 (복사 없음)**

이 저장소에서 Claude Code를 열고 입력합니다.

```
/blog-draft 국민연금 수령나이 티스토리
/blog-draft 국민연금 수령나이, 기초연금 신청방법 네이버
/blog-draft 에어프라이어 리뷰 네이버
/blog-draft 성수동 브런치 카페 장소 티스토리
```

- 키워드 뒤에 유형(`정보`, `리뷰`, `장소`)과 플랫폼(`티스토리`, `blogger`, `네이버`)을 붙입니다. 플랫폼을 생략하면 티스토리, 유형을 생략하면 키워드를 보고 판단합니다. 쉼표로 여러 키워드를 한 번에 줄 수 있습니다.
- Claude Code가 검색량과 연관 키워드를 조회하고, `docs/prompts/` 규칙에 따라 웹 검색으로 사실을 확인한 뒤 `drafts/2026-10-29-국민연금-수령나이-tistory.md` 같은 파일로 초안을 저장합니다. `drafts/`는 git에 올라가지 않습니다.
- claude.ai 프로젝트를 만들지 않아도 됩니다. 단, `docs/prompts/project-instructions.md`의 "내 블로그 정보"는 채워 두세요.

브리프만 터미널에서 확인하려면 이렇게 실행합니다.

```bash
npm run --silent brief -- "국민연금 수령나이" --platform tistory
npm run --silent brief -- "에어프라이어 추천" --platform naver --type review
npm run --silent brief -- "국민연금 수령나이" --structure C     # 구성 지정 (생략하면 무작위)
```

### 글이 매번 같은 틀이 되지 않게

같은 유형의 글이 쌓이면 구조와 말버릇이 반복되기 쉽습니다. 반복되는 패턴은 독자에게 "찍어낸 글"로 보이고, 검색 엔진은 대량 생성 콘텐츠로 판단할 수 있습니다. 그래서 두 가지 장치를 둡니다.

- **구성 변형**: 유형마다 구성 4가지(A~D)가 있고, 브리프를 만들 때 **무작위로 하나를 골라** `구성:` 줄에 넣습니다. 웹의 구성 선택이 `구성 자동`이면 복사할 때마다 새로 고릅니다.

  | 유형 | A | B | C | D |
  |---|---|---|---|---|
  | 정보 | 질문 답변형 | 결론 먼저형 | 상황으로 시작형 | 비교·표 중심형 |
  | 리뷰 | 요약 먼저형 | 사용 기간 순 | 장단점 중심형 | 비교형 |
  | 장소 | 정보 먼저형 | 방문 동선 순 | 추천 포인트형 | 상황별 가이드 |

- **문체 규칙** ([writing.md](docs/prompts/writing.md)): "오늘은 ~에 대해 알아보겠습니다", "도움이 되셨길 바랍니다" 같은 상투구를 금지하고, 도입 방식을 바꾸고, 표·자주 묻는 질문은 필요할 때만 넣게 합니다. 블로그의 말투와 관점은 모든 글에서 일정하게 유지합니다.

> 구성의 내용은 `docs/prompts/types/*.md`의 "구성 변형"에 정의돼 있습니다. 구성 이름을 바꾸면 `packages/collector/src/platforms.ts`의 `STRUCTURE_NAMES`도 함께 바꿔야 합니다.

> 네이버 검색광고는 "국민연금 수령나이" 같은 롱테일 키워드에 연관 키워드를 거의 주지 않습니다. 그래서 각 단어("국민연금", "수령나이")의 연관 키워드도 함께 조회한 뒤, 키워드의 단어를 많이 포함한 순으로 브리프에 넣습니다.

**방법 C. Claude 데스크톱 앱에서 대화로 (MCP, 추천)**

toolhub MCP 서버를 데스크톱 앱에 연결하면, Claude가 키워드 데이터와 글쓰기 규칙을 직접 조회합니다. 복사·붙여넣기도, 터미널도 필요 없습니다. 설정은 아래 [Claude 데스크톱 앱 연결 (MCP)](#claude-데스크톱-앱-연결-mcp)을 참고하세요.

```
오늘 뜬 키워드 중에 블로그로 쓸 만한 거 3개 골라줘
→ 2번으로 네이버 글 써줘
→ 저장하고 웹에서 열어줘      (초안 화면에서 미리보기·체크리스트·복사)
→ 어제 쓴 국민연금 글 도입부를 더 짧게 고쳐줘   (초안을 읽고 고쳐서 같은 파일에 저장, 이전 버전은 보관)
```

### 브리프 형식

직접 붙여넣을 때는 아래 형식을 따릅니다. 첫 줄을 보고 Claude가 작업을 구분합니다.

**① 글감 고르기** (선택): 오늘 쓸 키워드를 Claude에게 골라 달라고 할 때, 키워드 기록(검색량 순)의 상위 키워드를 표로 붙여넣습니다.

```
[글감 브리핑]
날짜: 2026-10-29
| 키워드 | 월간 검색량 | 경쟁도 | 소스 | 처음 본 시각 | 관련 뉴스 |
|---|---|---|---|---|---|
| 국민연금 | 287,000 | 낮음 | Google Trends | 13:49 | 국민연금 가입기간 늘려… |
```

→ 추천 글감 3~5개, 수명(상시·시즌·반짝), 타깃 키워드 후보, 제목 예시, 추천 유형, 추천 플랫폼을 받습니다.

**② 초안 받기**: ✍ 버튼이 만들어 주는 형식입니다. 키 설정에 따라 일부 항목은 빠집니다.

```
[글쓰기 브리프]
플랫폼: 티스토리
유형: 정보
구성: B (결론 먼저형)
키워드: 국민연금 수령나이
월간 검색량: 58,040 (PC 8,440 / 모바일 49,600) · 경쟁도: 중간
검색 추이: 꾸준함 — 1년 내내 검색량이 고르게 유지됩니다.
블로그 문서 수: 152,300 (검색량의 2.6배 · 포화도 보통)
연관 키워드 (관련 높은 순):
| 키워드 | 월간 검색량 | 경쟁도 |
|---|---|---|
| 국민연금 | 287,000 | 낮음 |
실제 질문 (지식iN):
- 1968년생 국민연금 언제부터 받나요?
상위 블로그 글 (겹치지 않는 각도를 잡기 위한 참고):
- 국민연금 수령나이 총정리 (2026-09-12)
```

리뷰 유형에는 **카페 글**(실제 후기), 장소 유형에는 카페 글과 **장소 정보**(이름·분류·주소)가 더 들어갑니다.

→ 제목 후보, 메타 설명, 태그, 플랫폼 형식의 본문, 이미지 목록, 사람이 할 일, 참고 출처, 스레드 홍보글 3개를 받습니다.

### 발행 전 직접 할 일

초안에는 사람이 채울 자리가 표시돼 있습니다. **AI 초안을 그대로 발행하지 마세요.** 검색 엔진과 애드센스는 사람이 다듬은, 경험이 담긴 글을 더 좋게 평가합니다.

| 표시 | 할 일 |
|---|---|
| `[이미지: 내용 \| alt: … \| 추천: …]` | 이미지를 직접 캡처·촬영하거나 무료 사진을 넣고, alt(대체 텍스트)를 입력합니다 |
| `[직접 작성: …]` | 내 경험이나 의견을 씁니다 |
| `[확인 필요: …]` | 공식 출처에서 확인한 뒤 고치거나 지웁니다 |

> 뉴스 사진이나 검색으로 찾은 이미지는 쓰지 마세요. 저작권 문제로 애드센스 승인 거절이나 정지 사유가 됩니다.

## Claude 데스크톱 앱 연결 (MCP)

### 설정 (처음 한 번)

1. 터미널에서 두 경로를 확인합니다.

   ```bash
   which node   # 예: /usr/local/bin/node
   pwd          # 저장소 루트에서 실행. 예: /Users/me/source/toolhub
   ```

2. 데스크톱 앱 설정 파일 `~/Library/Application Support/Claude/claude_desktop_config.json`의 `mcpServers`에 추가합니다. 경로는 1번에서 확인한 값으로 바꾸고, **반드시 절대 경로**를 씁니다. 다른 서버가 이미 있으면 그 옆에 추가합니다.

   ```json
   {
     "mcpServers": {
       "toolhub": {
         "command": "/usr/local/bin/node",
         "args": [
           "--env-file-if-exists=/Users/me/source/toolhub/apps/web/.env.local",
           "/Users/me/source/toolhub/packages/mcp/src/server.ts"
         ]
       }
     }
   }
   ```

3. 데스크톱 앱을 **완전히 종료(⌘Q)했다가 다시 실행**합니다. 대화창의 도구 메뉴에 `toolhub`가 보이면 연결된 것입니다.

> Claude Code는 저장소의 `.mcp.json`으로 같은 서버를 자동으로 인식합니다. 처음 열 때 사용 승인을 묻습니다.

### 쓸 수 있는 도구

**일정 관리** — 웹의 일정 관리와 같은 데이터(`data/tasks.json`)를 고칩니다.

| 도구 | 하는 일 |
|---|---|
| `list_tasks` | 할 일 목록 (오늘·다음 7일·날짜 없음·전체·완료). 프로젝트·태그·검색어로 거르기 |
| `add_task` | 할 일 추가. 한 말을 그대로 넣으면 자연어 빠른 추가처럼 해석 (날짜·시간·#태그·@프로젝트·!우선순위·반복) |
| `update_task` | 번호로 제목·상태·우선순위·마감일·시간·프로젝트·태그·반복·메모·링크 변경, 하위 할 일 추가 |
| `complete_task` | 완료 처리 (반복이면 다음 회차 자동 생성) |
| `delete_task` | 완전히 삭제 (되돌릴 수 없음) |
| `add_project` | 프로젝트 만들기 |

예: "이번 주 할 일 보여줘", "내일 오전 10시에 국민연금 글 검토 추가해줘 블로그 운영 프로젝트로", "17번 하위 할 일에 사진 촬영 추가해줘", "5번 완료", "오늘 고른 글감 3개를 이번 주 할 일로 잡아줘"

**블로그 자동화**

| 도구 | 하는 일 |
|---|---|
| `get_live_keywords` | 지금 실시간 키워드 조회 (오늘 기록에도 추가) |
| `get_daily_keywords` | 날짜별 기록을 검색량·경쟁도와 함께 `[글감 브리핑]` 표로 조회 |
| `analyze_keyword` | 키워드 검색량·경쟁도와 연관 키워드 |
| `research_keyword` | 24개월 검색 추이와 해석, 블로그 문서 수·포화도, 지식iN 질문, 상위 블로그 글, 최신 뉴스, 카페 글 (API HUB 키 필요) |
| `search_places` | 네이버 지역 검색으로 장소 이름·분류·주소 확인 (최대 5개, API HUB 키 필요) |
| `get_shopping_trend` | 쇼핑 분야 안에서 상품 키워드의 24개월 클릭 추이 (리뷰 글용, API HUB 키 필요) |
| `get_writing_rules` | `docs/prompts/`의 글감 선정·초안 작성 규칙 (유형·플랫폼별) |
| `get_writing_brief` | 키워드 + 플랫폼 + 유형 (+ 구성, 생략하면 무작위) → `[글쓰기 브리프]` |
| `save_draft` | 새 초안을 `drafts/`에 파일로 저장 |
| `list_drafts` | 초안 목록 (추천 제목·도입 첫 문장·사람이 채울 자리 수). 키워드를 주면 그 키워드로 쓴 초안만 — 새 글을 쓰기 전에 이미 쓴 주제인지, 최근 글과 시작이 겹치지 않는지 확인하는 데 씀 |
| `read_draft` | 초안 전체 읽기 |
| `update_draft` | 기존 초안을 고친 내용으로 덮어쓰기. 이전 버전은 `drafts/.history/`에 자동 보관 |
| `open_web` | toolhub 웹을 브라우저로 열기 (http://localhost:3100). **항상 로컬 main 브랜치의 최신 커밋으로 실행**하며, 꺼져 있거나 옛 커밋이면 (재)시작한 뒤 엽니다. 페이지(일정 관리 보기·실시간·기록·분석·초안·썸네일)와 키워드·날짜·초안 파일·썸네일 제목 지정 가능 |
| `stop_web` | `open_web`으로 시작한 웹 서버 끄기 (터미널에서 직접 띄운 서버는 끄지 않음) |

예: "toolhub 웹 열어줘"(일정 관리 오늘), "캘린더 열어줘", "어제 키워드 기록 화면 열어줘", "국민연금 수령나이 분석 화면 띄워줘", "방금 저장한 초안 웹에서 열어줘", "이 글 제목으로 썸네일 만들게 열어줘", "웹 서버 꺼줘"

#### `open_web`은 어떤 코드로 실행되나

| | 개발용 `npm run web` | 사용용 `open_web` |
|---|---|---|
| 주소 | http://localhost:3000 | http://localhost:3100 |
| 코드 | 지금 작업 중인 코드 (커밋 안 한 수정 포함) | **로컬 main 브랜치의 최신 커밋** |
| 실행 위치 | 이 저장소 | `~/.toolhub/runtime/toolhub` (git worktree) |
| 데이터·키 | `data/`, `apps/web/.env.local` | 같은 파일을 공유 |

- main에 커밋하면, 다음에 `open_web`을 부를 때 실행 폴더를 새 커밋으로 맞추고 웹을 재시작합니다. 커밋하지 않은 수정이나 다른 브랜치 작업은 반영되지 않습니다.
- 의존성(`package-lock.json`)이 바뀐 커밋이면 실행 폴더에 `npm install`을 다시 합니다. 오래 걸리면 Claude가 "준비 중"이라고 답하는데, 잠시 후 다시 요청하면 이어서 엽니다.
- `open_web`으로 시작한 웹 서버는 데스크톱 앱을 꺼도 계속 실행됩니다. 다 쓰면 "웹 서버 꺼줘"로 끄세요. 로그는 `.toolhub/web.log`에 남습니다.
- `git worktree list`에 실행 폴더가 함께 보이는 것은 정상입니다. 지우고 싶으면 `git worktree remove --force ~/.toolhub/runtime/toolhub`를 실행하면 되고, 다음 `open_web` 때 다시 만들어집니다.
- 3100번 포트를 다른 프로그램이 쓰고 있으면 MCP 설정의 `env`에 `"TOOLHUB_WEB_PORT": "3200"`처럼 다른 포트를 지정합니다.

대화창의 `+` 메뉴에서 **프롬프트**도 고를 수 있습니다.

- `blog_draft`: 키워드와 플랫폼을 넣으면 규칙과 브리프가 담긴 초안 요청이 만들어집니다.
- `pick_topics`: 그날 기록으로 글감 선정 요청을 만듭니다.

> MCP로 쓸 때는 claude.ai 프로젝트가 없어도 됩니다. Claude가 `get_writing_rules`로 규칙을 직접 읽습니다. 단, `docs/prompts/project-instructions.md`의 "내 블로그 정보"는 채워 두세요.

## 터미널에서 수집하기

웹을 띄우지 않고 터미널에서 바로 수집해 기록할 수도 있습니다.

```bash
npm run collect                            # 전체 소스
npm run collect -- --sources google,nate   # 일부 소스만
```

## 데이터

```
data/
  2026-10-29.json   # 하루에 파일 하나, 키워드당 한 줄
```

| 필드 | 설명 |
|---|---|
| `keyword` | 키워드 |
| `sources` | 잡힌 소스 (`google`, `nate`, `signal`) |
| `firstSeen` | 처음 본 시각 (KST) |

| `stats` | 네이버 검색광고 검색량·경쟁도. 아직 조회하지 않았으면 필드가 없고, 데이터가 없으면 `null` |

데이터 위치는 환경변수 `TOOLHUB_DATA_DIR`로 바꿀 수 있습니다.

### 테스트

외부 API를 부르지 않는 핵심 로직을 테스트합니다. 테스트 파일은 대상 파일 옆에 `*.test.ts`로 둡니다.

| 위치 | 테스트하는 것 |
|---|---|
| `packages/tasks` | 자연어 빠른 추가 해석, 날짜·반복 계산, 보기·그룹·정렬, 저장소(반복 완료·프로젝트 삭제·여러 프로세스 동시 쓰기) |
| `packages/collector` | 검색 추이 해석·포화도, 글쓰기 브리프·글감 브리핑 형식, 초안 파싱·도입 문장·고치기(백업·경로 차단), 키워드 병합·기간 집계 |
| `apps/web/lib` | 할 일 수정 요청 검증, 초안 미리보기 |

기능을 고치거나 버그를 찾으면 그 경우를 테스트에 추가해 두세요. 같은 버그가 다시 생기지 않습니다.

## 알아둘 점

- 네이트, signal.bz는 공식 API가 아닌 공개 엔드포인트를 사용합니다. 사이트가 바뀌면 해당 소스만 "조회 실패"로 표시되고, 나머지 소스는 계속 동작합니다.
- 네이버 검색광고 API는 호출 한도가 낮습니다. 요청 사이에 1초 간격을 두고, 한도에 걸리면 자동으로 재시도합니다.
- 검색 추이의 해석(시즌·급등 이력 등)과 포화도 기준은 경험칙입니다. 글감 판단의 참고로만 쓰고, 차트와 수치를 함께 보세요.
- 네이버 쇼핑 검색(상품 가격·목록) API는 API HUB로 옮겨지지 않고 종료돼 쓸 수 없습니다. 쇼핑 인사이트는 분야별 클릭 추이만 제공합니다.
- 네이버 검색광고 기준 검색량이 10 미만이면 `<10`으로 표시됩니다.
