# 블로그 글 → 인스타 게시물

블로그 글 하나에는 인스타 게시물 4~6개가 들어 있습니다. 대부분은 하나만 뽑고 나머지를 버립니다.

## 입력

toolhub 초안(`read_draft`) 또는 붙여넣은 글. 전부 읽은 뒤에 고릅니다.

## 요약하지 말고 뽑아내기

글을 요약한 건 릴스가 아닙니다. 따로 떼어도 서는 것들을 찾습니다.

| 뽑을 것 | 무엇 |
|---|---|
| 주장 | 논쟁을 시작할 만한 문장 |
| 숫자 | 금액, 기간, 비율, 날짜 |
| 이야기 | 사람·장면·대가가 있는 순간 (발행할 때 덧붙인 내 경험) |
| 방법 | "실제로는 이렇게 돌아가요" 하는 설명 |
| 실수 | 잘못했던 것을 인정하는 부분 |
| 한 줄 | 그대로 인용할 만한 문장 |

쓰기 전에 찾은 것을 개수와 함께 보여 줍니다. 4개 미만이면 얇은 글이고, 억지로 4개를 만들면 4개 다 얇습니다. 그렇다고 말합니다.

## 뽑은 것마다 형식 고르기

- **주장·실수·이야기 → 릴스.** 목소리와 얼굴(또는 손·화면)이 필요합니다 (`reel.md`).
- **방법·번호 목록 → 캐러셀.** 다시 읽어야 합니다 (`carousel.md`).
- **인용할 한 줄 → 스토리 한 장** (`story.md`). 그리고 블로그 글로 보내는 **링크 스티커 스토리**는 항상 하나 만듭니다.

## 한 주 구성

- 게시물마다 **완전히 따로** 섭니다. 보는 사람은 블로그 글을 보지 않았습니다. "지난 글에서 말했듯이"는 쓰지 않습니다.
- 게시물마다 다른 훅 공식을 씁니다. 같은 모양의 훅 다섯 개는 공장처럼 보입니다.
- 순서: 가장 센 주장 먼저, 이야기는 주 중반, 방법은 마지막(앞 게시물을 좋아한 사람이 기다릴 때).

## 출력

```
원본: "연말정산 모의계산 하다 막히는 질문 6가지" (블로그, 약 2,400자)

찾은 것  주장 3 · 숫자 9 · 이야기 1 · 방법 4 · 실수 1 · 한 줄 3

한 주
화  릴스     #19 마감 임박      "연말정산 미리보기, 12월 18일에 닫혀요"
수  캐러셀   방법 5장           모의계산 결과가 '납부'일 때 바꿀 수 있는 것
금  릴스     #1 손해 고백       "월세 공제 몰라서 17만원 놓쳤어요"
토  스토리   링크 스티커 3장     전체 글로 보내기

"화요일 거 써줘"라고 하면 하나씩 씁니다.
```

한 번에 하나씩, 요청할 때 씁니다. 네 개를 한꺼번에 쓰면 다 비슷해지고 하나도 안 찍게 됩니다.
