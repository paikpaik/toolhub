# 초안 작성 규칙 (`[글쓰기 브리프]`)

모든 글 유형에 공통인 규칙입니다. 글 구조(구성 변형)와 사람이 채울 자리의 기준은 브리프의 `유형`에 맞는 `types/*.md`를 함께 따릅니다.

## 입력 형식

toolhub가 만든 브리프입니다. 키 설정에 따라 일부 항목이 빠질 수 있습니다.

```
[글쓰기 브리프]
플랫폼: 티스토리            (티스토리 | Blogger | 네이버)
유형: 정보                  (정보 | 리뷰 | 장소)
구성: B (결론 먼저형)        (types/*.md의 구성 변형 A~D 중 하나)
키워드: 국민연금 수령나이
월간 검색량: 58,040 (PC 8,440 / 모바일 49,600) · 경쟁도: 중간
검색 추이: 꾸준함 — 1년 내내 검색량이 고르게 유지됩니다.
블로그 문서 수: 152,300 (검색량의 2.6배 · 포화도 보통)
연관 키워드 (관련 높은 순):
| 키워드 | 월간 검색량 | 경쟁도 |
|---|---|---|
| 국민연금 | 287,000 | 낮음 |
| ... |
실제 질문 (지식iN):
- 1968년생 국민연금 언제부터 받나요?
- ...
상위 블로그 글 (겹치지 않는 각도를 잡기 위한 참고):
- 국민연금 수령나이 총정리 (2026-09-12)
- ...
카페 글 (실제 후기·고민):        (리뷰·장소 유형에만)
- ...
장소 정보 (네이버 지역 검색):    (장소 유형에만)
| 이름 | 분류 | 도로명 주소 | 링크 |
참고: (선택. 글 각도, 직접 경험 메모 등)
```

| 항목 | 쓰는 방법 |
|---|---|
| 구성 | `types/*.md`의 같은 문자 변형 구조로 씁니다. 글마다 구조가 같아지지 않도록 toolhub가 골라 준 것이므로 다른 구성으로 바꾸지 않습니다 |
| 연관 키워드 | 메인 키워드의 단어를 포함한 것이 앞에 오고, 뒤로 갈수록 넓은 관심사입니다. 주제와 먼 키워드는 쓰지 않아도 됩니다 |
| 검색 추이 | `시즌`이면 시기를 제목·도입에 반영하고(예: "2027년 연말정산"), `급등 이력`·`하락세`면 지나간 이슈보다 오래 유효한 정보 위주로 씁니다 |
| 블로그 문서 수·포화도 | 포화도가 `높음`이면 이미 비슷한 글이 많다는 뜻입니다. 더 좁은 롱테일 각도나 상위 글에 없는 정보로 차별화합니다 |
| 실제 질문 | 검색자가 실제로 묻는 질문입니다. 소제목과 "자주 묻는 질문"을 우선 여기서 고릅니다. 질문 문장을 그대로 베끼지 말고 일반화합니다 |
| 상위 블로그 글 | 이미 상위에 있는 글의 제목입니다. **같은 구성·제목을 피하고**, 빠진 정보나 다른 관점으로 씁니다. 글을 열어 내용을 베끼지 않습니다 |
| 카페 글 | 실제 사용자의 후기·고민입니다. 장단점과 "이런 분께 추천/비추천"을 정리하는 데 참고합니다 |
| 장소 정보 | 장소의 공식 이름·분류·주소입니다. 이 정보와 다르게 쓰지 않고, 영업시간·가격처럼 없는 정보는 웹 검색으로 확인해 쓰거나, 확인하지 못하면 "방문 전 공식 채널에서 확인하세요"처럼 씁니다 |

- `월간 검색량: 조회하지 않음`이거나 항목이 빠져 있으면 있는 정보만으로 작성하고, 부족한 검색 의도는 웹 검색으로 보완합니다.

## 작성 순서

1. **검색 의도 파악**: 키워드, 연관 키워드, 실제 질문을 보고 검색자가 알고 싶은 질문 3~5개를 정합니다.
2. **차별화 각도**: 상위 블로그 글 제목과 포화도를 보고, 같은 내용을 반복하지 않을 각도를 한 줄로 정합니다.
3. **사실 확인**: 웹 검색으로 최신 정보를 확인합니다. 지침의 "사실 확인" 원칙을 따릅니다.
4. **구성 → 작성**: `유형`에 맞는 `types/*.md`에서 `구성`의 변형 구조로, 아래 문체 규칙을 지켜 씁니다.
5. **플랫폼 형식 적용**: `플랫폼`에 맞는 `platforms/*.md` 규칙으로 본문을 출력합니다.
6. **내보내기 전 확인**: 아래를 직접 세어 보고, 어긋나면 고친 뒤 내보냅니다.
   - **분량**: 본문 글자 수(공백 포함, `[이미지: …]`·`■`·`★` 빼고)가 플랫폼 규칙의 범위 안인지. 모자라면 검색자가 궁금해할 질문의 답, 구체적인 예시·계산, 상황별 판단을 더해 채웁니다. 같은 말을 되풀이하거나 빈말로 늘리지 않습니다.
   - **제목**: 플랫폼 규칙의 글자 수 범위 안인지.
   - **메인 키워드 횟수**: 본문 문장 속에서 플랫폼 규칙의 횟수 안인지 (이미지 자리의 설명·alt는 세지 않음).
   - **표시**: 본문에 `[이미지: …]` 말고 다른 표시(`[직접 작성]`, `[확인 필요]`, `[블로그 링크]` 등)가 없는지. 날짜·금액은 확인한 출처가 있는 것만 단정합니다.

## 문체 규칙

글이 여러 편 쌓여도 같은 틀·같은 말버릇이 반복되지 않게 합니다. 반복되는 패턴은 독자에게 "찍어낸 글"로 보이고, 검색 엔진은 대량 생성 콘텐츠로 판단할 수 있습니다.

- **말투와 관점은 일정하게**: 지침의 "내 블로그 정보"의 말투·글쓴이 관점은 모든 글에서 유지합니다. 바뀌어야 하는 것은 구조와 표현입니다.
- **쓰지 않는 상투구**:
  - 시작: "오늘은 ~에 대해 알아보겠습니다", "~에 대해 궁금하신 분들 많으시죠?", "안녕하세요, ~입니다"
  - 끝: "도움이 되셨길 바랍니다", "이상으로 ~였습니다", "궁금한 점은 댓글로 남겨주세요", "지금까지 ~에 대해 알아보았습니다"
  - 본문: "~라고 할 수 있습니다", "~하는 것이 중요합니다", "다양한", "효과적인", "꼭 알아두세요" 같은 빈말의 반복
- **도입은 매번 다른 방식으로**: 질문, 구체적인 상황, 숫자·사실 하나, 결론 중에서 구성에 맞는 것을 고릅니다. 글 첫 문장을 키워드 반복으로 시작하지 않습니다.
- **마무리는 짧게, 요약을 반복하지 않게**: 본문을 다시 나열하지 말고 다음 행동이나 한 줄 판단으로 끝냅니다.
- **표·목록·자주 묻는 질문은 필요할 때만**: 정리할 정보가 있을 때 씁니다. 모든 글에 기계적으로 넣지 않습니다.
- **문장 길이를 섞기**: 짧은 문장과 긴 문장을 섞고, 같은 어미("~습니다.")가 세 문장 이상 연속되지 않게 합니다.
- **소제목은 검색자의 말로**: "개요", "결론" 같은 형식적인 소제목 대신 실제 질문이나 구체적인 표현을 씁니다.

## 키워드 사용

- 메인 키워드: 제목 앞쪽, 도입 첫 문단, 소제목 1~2곳에 자연스럽게 넣습니다.
- 연관 키워드: 관련 높은 순으로 소제목과 본문에 자연스럽게 녹입니다. 억지로 다 넣지 않습니다.
- 같은 키워드를 문장마다 반복하는 키워드 남용은 하지 않습니다.

## 사람이 채울 자리

본문은 **복사해서 바로 올릴 수 있는 완성된 글**로 씁니다. 본문에 남기는 표시는 이미지 자리 하나뿐입니다 (이미지는 어차피 사람이 넣어야 하므로). 개수와 위치의 기준은 `types/*.md`를 따릅니다.

- **이미지 자리** (본문에 넣음)
  ```
  [이미지: 무엇을 보여주는 이미지인지 | alt: 대체 텍스트 | 추천: 직접 캡처 / 직접 촬영 / 무료 사진(검색어: 영문 검색어)]
  ```
  - 예: `[이미지: 국민연금공단 홈페이지 예상 연금액 조회 화면 | alt: 국민연금 예상연금 조회 화면 | 추천: 직접 캡처]`
  - 공식 사이트 화면, 직접 만든 표, 직접 찍은 사진처럼 **직접 만들 수 있는 이미지**를 우선 추천합니다.
- **직접 경험** (본문에 넣지 않음): `[직접 작성: …]` 같은 빈자리를 본문에 두지 않습니다. 경험이 들어갈 자리도 일반적인 설명으로 완성된 문장을 쓰고, 지어낸 경험은 쓰지 않습니다. 넣으면 좋은 경험은 출력 형식의 **사람이 할 일**에 "어느 소제목 아래에 무엇을" 형태로 제안합니다.
  - 예: `- (선택) "결과가 납부로 나오면" 아래: 내 모의계산 결과와 연금계좌 납입액을 바꿔 봤을 때 달라진 금액`
- **확인 못 한 정보** (본문에 넣지 않음): `[확인 필요: …]` 표시를 본문에 두지 않습니다. 본문에는 웹 검색으로 확인한 내용만 씁니다. 확인하지 못한 내용은 본문에서 빼거나, 단정하지 않고 확인할 곳을 알려 주는 문장("정확한 운영 기간은 국세청 공지에서 확인하세요")으로 씁니다. 그렇게 처리한 내용은 **사람이 할 일**에 적습니다.

## 출력 형식

아래 순서로 출력합니다. 각 항목은 제목(`##`)으로 구분합니다.

1. **제목 후보 3개**: 메인 키워드를 앞쪽에 넣고, 플랫폼 규칙의 글자 수를 지킵니다. 추천 1개는 제목 끝에 ` (추천)`을 붙여 표시합니다 (예: `1. 국민연금 수령나이, 출생연도별로 한눈에 정리 (추천)`). `⭐`, `←`, 글자 수 같은 다른 표시는 붙이지 않습니다.
2. **메타 설명**: 플랫폼 규칙에 따릅니다.
3. **태그**: 플랫폼 규칙의 개수를 지킵니다. 쉼표로 구분합니다.
4. **본문**: 플랫폼 형식으로, 복사하기 쉽게 **코드 블록 하나**에 담습니다.
5. **이미지 목록**: 본문의 `[이미지: …]` 표시를 순서대로 다시 정리한 표 (번호, 위치(소제목), 내용, alt, 추천 방법).
6. **사람이 할 일**: 본문 밖에서 정리합니다. ① 넣으면 좋은 경험(선택, 위치와 내용) ② 확인하지 못해 빼거나 돌려 쓴 내용 ③ 발행 전 확인 사항.
7. **참고한 출처**: 사실 확인에 사용한 공식 출처 링크.
8. **스레드 홍보글**: `threads.md` 규칙에 따릅니다.
